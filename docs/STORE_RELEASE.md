## Android (Google Play)

### 1. Shared release keystore (same as native WithTable)
Uses repo-root [`PosBillingwala.jks`](../../PosBillingwala.jks) via [`build-release.sh`](../../build-release.sh):

| Setting | Value |
|---------|--------|
| File | `PosBillingwala.jks` (repo root) |
| Alias | `posbillingwala` |
| Password | `PosBillingwala` (override with `STORE_PASSWORD` / `KEY_PASSWORD`) |

Flutter reads this through `pos_billingwala_v2/android/key.properties` (gitignored; regenerated by the script).

### 2. Configure signing (Flutter)
Already wired if you use the script. Manual:

```bash
cp pos_billingwala_v2/android/key.properties.example pos_billingwala_v2/android/key.properties
# Defaults match build-release.sh (PosBillingwala.jks + alias/password)
```

### 3. Build App Bundle

**Recommended (copies into `releases/POS-Flutter/`):**
```bash
./build-release.sh flutter aab
# or:  ./build-release.sh flutter both
```

**Or Flutter CLI:**
```bash
cd pos_billingwala_v2
flutter pub get
flutter build appbundle --release
```
Output: `build/app/outputs/bundle/release/app-release.aab`

### 4. Play Console checklist
- [ ] App name: **POS Billingwala**
- [ ] Application ID: `com.pos_billingwala` (same as native WithTable — treat as update or replace carefully)
- [ ] Privacy policy URL
- [ ] Store listing screenshots (phone + 7" / 10" if tablet)
- [ ] Content rating questionnaire
- [ ] Target API / Data safety form (licence, FCM, device ID)
- [ ] Upload AAB to **internal testing** first
- [ ] Firebase `google-services.json` already included for this package
- [ ] Promote to closed/open testing, then production

> **Conflict note:** Installing this release uninstalls / replaces the native WithTable build on the same package name. Coordinate rollout with existing users.

## iOS (App Store)

### 1. Xcode project
```bash
cd pos_billingwala_v2/ios
pod install
open Runner.xcworkspace
```
Set **Team**, **Bundle Identifier** (e.g. `com.posbillingwala.app`), signing certificates.

### 2. Capabilities
- Push Notifications
- Background Modes → Remote notifications (for FCM)

### 3. Build IPA
```bash
flutter build ipa --release
```

### 4. App Store Connect checklist
- [ ] App Privacy (device ID, purchase/licence data, notifications)
- [ ] Screenshots for required device sizes
- [ ] Export compliance / encryption questionnaire (standard HTTPS → usually “uses encryption, exempt”)
- [ ] TestFlight internal build before production
- [ ] Local Network usage for Wi‑Fi ESC/POS printers (Info.plist keys included)

### 5. Printing on iOS
- Prefer **network ESC/POS** (Settings → Printer host / port, usually `9100`)
- Fallback: **Share** receipt text / AirPrint-capable apps
- Classic Bluetooth SPP is not available like Android

## Privacy & data (form answers)

Declare only what the app actually does:

| Data | Collected? | Purpose | Notes |
|------|------------|---------|--------|
| Device ID / install ID | Yes | Account security / licence binding | Local + API |
| Name / business name | Yes | Licence session | From login |
| Email / phone | If entered at register | Account | Trial/register |
| Purchase / licence status | Yes | App functionality | Server-validated |
| Push token (FCM) | Yes | Notifications | Mess / licence / promo |
| App activity (bills, products) | Yes | Core POS + sync | Stored locally; synced to your backend |
| Approximate location | No* | — | Don’t declare unless you add it |
| Photos / contacts | No | — | Unless you later add gallery pickers |

\*Confirm no location permission is requested in the current build before submitting.

**Permissions users may see**
- Internet / network
- Notifications (FCM)
- Bluetooth (Android printer)
- Local network (iOS Wi‑Fi printer)

Privacy policy should mention: licence login, local SQLite storage, sync to `posbillingwala.com` APIs, FCM, and printer connectivity.

## Versioning
`pubspec.yaml` → `version: X.Y.Z+BUILD`  
- `X.Y.Z` = user-facing versionName / CFBundleShortVersionString  
- `BUILD` = versionCode / CFBundleVersion (must increase every store upload)

Current: **2.0.1+2**
